# SOLON Blog Article

Create one new article for the SOLON Agency blog (a digital agency for lawyers). The **only file you create manually** is the Markdown source in `blog/posts/`; everything else is generated by the scripts. All content is in **Romanian with correct diacritics** (ă, â, î, ș, ț) and persuasive towards creating a digital need in the legal proffesional reader - a digital need which can be fulfilled by SOLON, the digital agency for lawyers.

## Workflow

```
- [ ] 1. Read 1-2 recent articles in blog/posts/ to calibrate tone, depth, structure
- [ ] 2. Create blog/posts/[slug].md with frontmatter + content
- [ ] 3. Insert the provided images (or pick fitting undraw_*.png from assets/img/)
- [ ] 4. node scripts/humanize.js
- [ ] 5. node scripts/build.js
- [ ] 6. node scripts/update-sitemap.js
- [ ] 7. node scripts/append-blog-google-sheets.js "ARTICLE_TITLE"
```

Run the four scripts in this exact order. Step 7 takes the article title (with diacritics) as the argument and needs network access.

## Step 1 — Calibrate

Read at least one recent post in `blog/posts/` (e.g. `cum-sa-folosesti-docusign-ca-avocat.md`) before writing, to match tone, depth and link style.

## Step 2 — Markdown file

Filename: `blog/posts/[slug].md`. The `[slug]` is lowercase, hyphens, **no diacritics** (e.g. `cum-sa-folosesti-slack-ca-avocat`). It must match the `slug` frontmatter field and the folder `build.js` generates under `blog/`.

### Frontmatter (all fields required)

```yaml
---
title: "Cum să folosești [Instrument] ca avocat"
date: "YYYY-MM-DD"
slug: "cum-sa-folosesti-[instrument]-ca-avocat"
description: "Ghid practic pentru avocați: [2-3 topice separate prin liniuțe]."
read_time: 13
categories: ["digitalizare", "productivitate", "automatizări"]
tags: ["[instrument]", "avocați", "productivitate", "[topic1]", "[topic2]"]
---
```

| Field | Rules |
|---|---|
| `title` | Romanian, diacritics. **Max 50 characters.** |
| `date` | `YYYY-MM-DD`, today's date. |
| `slug` | Matches filename + folder. No diacritics, lowercase, hyphens. |
| `description` | Romanian. **Up to 130 characters.** Used in meta + blog card. |
| `read_time` | Integer minutes (~200 words/min). Omit to auto-calculate. |
| `categories` | From: `digitalizare`, `productivitate`, `automatizări`, `legaltech`, `management`, `calendar`, `securitate`, `seo`, `marketing juridic`. |
| `tags` | Lowercase. Always include `avocați` and the tool name. Max 7. |

### Content rules

- **Language**: Romanian with diacritics. Address the reader as "tu" (not "dumneavoastră"). Professional, direct, practical, no marketing fluff.
- **Be correct, precise, specific**: name exact menu paths, setting names, shortcuts, version-specific features, real standards. Avoid vague claims. Stay factually accurate about the tool — describe its real features and its limits honestly.
- **Length**: at least 1000 words of varying complexity.
- **Structure**: 2-3 sentence intro (what the tool is, why it matters for lawyers, what the article covers) → numbered H2 sections (`## 1. Titlu`) → **Concluzie**. Minimum **10 sections**; aim for 11-15.
- **SEO**: target long-tail keywords naturally in headings and body.
- **Internal links**: link several other articles using relative paths `[text](../alt-slug/)`. See existing slugs in `blog/posts/`.
- **Formatting**: `**bold**` for UI names/menu paths/key concepts; `` `code` `` for shortcuts, paths, operators, field names, values; bullet lists for features, numbered lists for sequential steps; tables for comparison schemas; fenced code blocks for structure diagrams.
- Do NOT use inline styles, HTML comments, or custom CSS classes in the body.

### Suggested sections (adapt names to the tool)

1. Configurare de bază — 2. Organizare/structură — 3. Clasificare vizuală — 4. Automatizări — 5. Căutare avansată — 6. Șabloane/conținut reutilizabil — 7. Integrare cu alte instrumente (third-party) — 8. Colaborare și delegare — 9. Securitate și conformitate (GDPR, secret profesional) — 10. Aplicația mobilă — 11. Tips & tricks (min. 7 concrete) — 12. Concluzie.

### Mandatory SOLON call-to-action (end of Concluzie)

End the Concluzie with the value summary, one honest trade-off/limitation, then a sentence in this format:

> Dacă dorești să [implementezi/configurezi/integrezi] [instrument] pentru cabinetul tău [adaptat specificului / cu automatizări / cu integrare cu ...], echipa **SOLON** oferă consultanță de digitalizare adaptată specificului practicii tale juridice.

## Step 3 — Images

If the user provides images, use those. Otherwise pick fitting `undraw_*.png` files from `assets/img/` (check with a glob).

- Path prefix is **always** `../../assets/img/FILENAME.ext` (relative to compiled `blog/[slug]/index.html`).
- Place the **first image right after the intro paragraph**, before the first H2.
- Space later images at natural breaks, 4-5 sections apart — do not cluster.
- Use `col-md-8` for wide/landscape, `col-md-9` (or `col-md-7`) for portrait/square.
- Wrap every image in this exact block:

```html
<div class="row justify-content-center my-4">
  <div class="col-md-9">
    <img src="../../assets/img/FILENAME.ext" alt="Ilustrație: [descriere în română, relevantă juridic]" class="img-fluid rounded shadow-sm" loading="lazy" decoding="async" />
  </div>
</div>
```

## Steps 4-7 — Build pipeline

```bash
node scripts/humanize.js          # normalises typography (em dashes → hyphens)
node scripts/build.js             # compiles .md → HTML, regenerates posts.json + blog/index.html
node scripts/update-sitemap.js    # adds the new URL to sitemap.xml (priority 0.80)
node scripts/append-blog-google-sheets.js "TITLU ARTICOL"   # logs the article; needs network
```

`build.js` creates `blog/[slug]/index.html`, updates `blog/posts.json` (sorted by date desc) and regenerates `blog/index.html`. Pass the exact title (with diacritics) to the last script.
